# Spec: Photo Ledger v1

Status: ready-for-agent

## Problem Statement

用户的日常消费大量发生在电商/支付 App 里，每一笔都留有订单详情页截图，但这些截图只是躺在相册里的图片：想记账时需要手动把商家、日期、实付款金额逐项抄进记账 App，繁琐到坚持不下来。云端记账方案又要求把消费数据交给第三方，用户不愿意。

用户想要的是：把已经存在的订单截图随手丢进一个 App，手机上的 AI 自己把账记好——数据从头到尾不出设备。

## Solution

Photo Ledger 是一个纯本地 Android 应用。用户从相册选择订单截图、或从微信/相册直接分享进来，App 用端侧多模态大模型（Qwen3-VL-4B，经 llama.cpp 运行）将截图提取为一张待确认的账目草稿；用户确认或修正后成为正式的账目记录。记录支持手工新增编辑、按类别与月份汇总、CSV 导出与 JSON 备份（可回灌）。模型文件首次使用时引导下载（官方源/国内镜像可切换）或从本地文件导入。全程无账号、无云端、数据不出设备。

## User Stories

### 导入

1. As a 用户, I want 在 App 内点"+"从相册选择一张或多张订单截图, so that 我能把相册里已有的截图变成账目
2. As a 用户, I want 在相册或微信里看到订单截图时直接"分享到照片记账", so that 不需要先退出当前 App 再打开记账 App
3. As a 用户, I want 一次选多张截图后它们进入导入队列、逐张自动提取并显示进度, so that 我可以一次导入一周的截图然后去干别的
4. As a 用户, I want 队列中某张截图提取失败时不阻塞后面的截图, so that 一张坏图不毁掉整批导入
5. As a 用户, I want 重复分享同一张截图时 App 提示"这张已导入过", so that 我不会不小心记两笔一样的账
6. As a 用户, I want 队列里每一项都能看到当前状态（排队/提取中/成功/失败）, so that 我知道哪些账已经记好、哪些还需要我处理

### 提取与确认

7. As a 用户, I want App 自动从截图提取商家、日期（付款时间优先）、实付款金额、币种和类别建议, so that 我几乎不用手动输入
8. As a 用户, I want 提取结果以 Draft（草稿）呈现，我确认后才成为正式账目记录, so that AI 提错不会直接污染我的账本
9. As a 用户, I want 在确认前修改草稿的任何字段（金额、日期、商家、类别）, so that AI 的小错误我一键就能修正
10. As a 用户, I want 草稿界面上能看到原始截图（可放大）, so that 我能对照原图核对提取结果
11. As a 用户, I want 提取失败（比如截图不是订单页）时保留截图并给我一张空表单, so that 我可以手工填成一条记录，而不是白白丢掉这张图
12. As a 用户, I want 可以明确放弃一张草稿, so that 不想要的提取结果不会一直挂着
13. As a 用户, I want 提取的"订单状态"文本（如"已退款"）显示在草稿里, so that 我能看到原订单状态并自行决定这条账怎么处理

### 记账本

14. As a 用户, I want 一条账目记录包含金额（实付款口径）、日期（付款时间口径）、商家、类别、币种和缩略图, so that 我日后能翻出这笔消费的来龙去脉
15. As a 用户, I want 手工新增一条不含截图的账目记录, so that 没有截图的消费也能记账
16. As a 用户, I want 编辑和删除已有的账目记录, so that 记错的账能改
17. As a 用户, I want 按月份查看账目列表和各月汇总, so that 我知道每个月花了多少
18. As a 用户, I want 按类别查看汇总（本月各类别合计）, so that 我知道钱花在了哪类消费上
19. As a 用户, I want 点开记录里的缩略图查看原始截图, so that 我能随时核对当时的提取对不对
20. As a 用户, I want 删除记录时可以选择是否连原始截图一起删, so that 相册之外不留我没用的图片占存储

### 类别

21. As a 用户, I want App 内置一套默认中文类别（餐饮、购物、交通、居住、医疗、娱乐、通讯、其他）, so that 装完就能用，不用先建分类体系
22. As a 用户, I want 新增/重命名/删除自定义类别, so that 类别贴合我的消费结构
23. As a 用户, I want 提取时模型从我的类别列表（含自定义）中选择归类建议, so that 类别建议和我自己的体系一致
24. As a 用户, I want 删除一个类别时其下记录改为"其他"而不是被删掉, so that 删类别不丢账

### 模型管理

25. As a 用户, I want 首次使用时引导我下载模型文件并显示进度, so that 我不需要懂什么是 GGUF 也能完成设置
26. As a 用户, I want 下载源在官方 HuggingFace 与 hf-mirror 镜像之间切换, so that 国内网络也能下载成功
27. As a 用户, I want 从本地文件导入模型（电脑下载后传到手机）, so that 下载不可用时我还有兜底
28. As a 用户, I want 手机内存不足以加载模型时得到明确提示而不是崩溃, so that 我知道这台设备跑不了而不是怀疑 App 坏了
29. As a 用户, I want 低内存设备（<8GB RAM）在安装/首启时就被提示不满足要求, so that 不至于下载完 2.8GB 才发现用不了

### 数据出与进

30. As a 用户, I want 手动导出全部账目为 CSV（UTF-8 BOM）, so that 我能在 Excel 里打开或迁移到其他工具
31. As a 用户, I want 手动导出 JSON 备份（含账目记录与自定义类别）, so that 我有换机或清数据时的保险
32. As a 用户, I want 从 JSON 备份导入恢复账目记录与类别, so that 换手机/清数据后账本能回来
33. As a 用户, I want 知道 CSV 只是给人看的（不能回灌）、JSON 备份才是恢复手段, so that 我在需要恢复时不会拿错文件

### 隐私

34. As a 用户, I want 账目数据、截图、提取结果 100% 留在本机, so that 我的消费记录不属于任何公司
35. As a 用户, I want App 仅在下载模型文件时联网，其余时候完全离线工作, so that 装好模型之后飞行模式也能正常记账

## Implementation Decisions

### 架构与既定 ADR

- **提取路线**：VLM 端到端（ADR-0001）。PaddleOCR 两段式仅为质量闸门失败时的备胎，v1 不实现。
- **运行时与模型**：llama.cpp 自建 NDK 编译 + JNI 绑定；模型主选 Qwen3-VL-4B-Instruct Q4_K_M（约 2.8GB），原型阶段与 MiniCPM-V 4.5 int4 对比后定稿（ADR-0002）。
- **本地优先边界**（ADR-0003）：联网仅限模型下载；无账号、无云同步、无崩溃上报。
- **技术栈**：Kotlin + Jetpack Compose + Room (SQLite) + 协程。包名 `io.github.pnickzhangq.photoledger`，显示名"照片记账"。
- **存储**：Room 存账目记录、类别、草稿、照片路径、内容哈希；照片原图存 App 私有目录，数据库只存路径与缩略图。JSON 仅是备份文件的序列化格式，不是存储介质。

### 模块划分（接口层面的约定）

- **提取引擎 (Extraction Engine)**：输入位图 + 提示词配置，输出 Draft。内部封装 llama.cpp JNI、GBNF 约束解码（以 JSON Schema 生成的文法约束输出）、JSON 解析与字段口径归一（实付款/付款时间）。该模块以桌面端与 Android 端可共用的形式实现——桌面端跑质量闸门，Android 端跑产品，共享同一套 prompt、grammar 与解析逻辑。
- **导入队列 (Import Queue)**：输入截图 URI 列表，逐张产出状态事件（去重命中/排队/提取中/成 Draft/失败）。去重按图片内容哈希。队列是单一编排点：分享进入与相册进入都汇入同一队列。
- **账目库 (Ledger)**：Draft 的确认/修正/放弃，Entry 的增删改查，按月份与类别的汇总查询，Room schema 管理。
- **类别管理 (Categories)**：默认中文类别的种子数据，自定义增删改；删除类别时其下 Entry 归入"其他"。提取时把当前类别列表注入 prompt。
- **模型管理 (Model Manager)**：模型文件下载（源可切换：HF 官方 / hf-mirror；支持断点）、本地文件导入、加载、内存预检（RAM 低于 8GB 明确拒绝并提示）。
- **备份与导出 (Backup & Export)**：JSON 备份（含 Entry 与自定义 Category，不含照片；可出可进，round-trip 无损是硬要求）与 CSV 导出（UTF-8 BOM，只出不进）。
- **UI (Compose)**：导入队列界面、草稿确认界面（左侧原图可缩放、右侧字段表单）、流水列表（按月分组）、月度/类别汇总页、类别管理页、模型设置页、备份导出页。

### 提取字段契约

Draft 字段：商家、日期（标注来源口径：付款时间或下单时间）、实付款金额、币种（默认 CNY）、订单状态文本、类别建议（从用户类别列表中选）。明细行不在 v1 契约内。

### 质量闸门（ADR-0001 的验收标准）

在投入 Android 端集成之前，先在桌面环境（同一模型 + 同一 prompt + 同一 grammar）用用户提供的真实订单截图数据集验证：硬字段（实付款金额、日期）≥95% 完全正确；软字段（商家、类别）≥80% 且错误可一眼修正。不达标触发备选路线讨论，不硬上。这是第一张实施票。

## Testing Decisions

测试只断言外部行为，不断言实现细节。四个已确认的接缝（seams），按此设计测试：

- **S1 提取管道整体**：以数据集驱动测试（非单元测试）——真实截图进、Draft 字段出，断言质量闸门数字。此缝测真模型；跑在桌面端，标记为独立于 CI 的验收任务。模型替换、prompt 调整、口径变更都必须重跑此数据集。
- **S2 导入队列**：JVM 级测试，注入假提取器（fake），断言：批量顺序处理、单张失败不阻塞、哈希去重命中提示、状态事件序列正确。
- **S3 Draft→Entry 确认流**：JVM 级测试 + Room 内存库，断言：确认才落库、放弃不留痕、手工空表单可成 Entry、删类别后其下 Entry 归"其他"。
- **S4 备份/导出**：JVM 级测试，断言 JSON 备份 round-trip（出→进，记录与类别无损）；CSV 仅断言格式（UTF-8 BOM、列头、金额与日期的序列化）。

不单独开缝：模型下载/加载（真机人工验证）、Compose UI 层、缩略图生成（S3 顺带覆盖）。原则：S1 测质量用真模型，S2–S4 测逻辑用假模型，互不拖累。

## Out of Scope

- 明细级提取（逐商品行）——ADR-0001 只要求汇总级
- 多张截图合并一条记录（预售定金+尾款场景）——用户手改金额代替
- 退款作为领域概念、订单状态参与任何账目逻辑——状态仅展示
- 图表、预算、趋势分析——后续迭代
- 多币种换算——币种作为字段保留，但不做汇率
- 云同步、账号、自动备份到任何第三方——被 ADR-0003 明确禁止
- 应用上架、开源发布
- Android 10 以下、RAM < 8GB 的设备支持（提示后可安装但不保证可用）
- iOS / 桌面 App（桌面环境仅作为质量闸门的测试场，不做产品）
