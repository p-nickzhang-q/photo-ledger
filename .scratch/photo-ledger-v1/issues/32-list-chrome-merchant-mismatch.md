## 背景 / 动机

用户真机导入一张淘宝闪购订单列表截图（一图两单：如意馄饨 ¥16 / 悸动 ¥15.6），
第一单商户被回填成「**飞猪**」——飞猪是顶部标签栏「飞猪旅行」里的字。

用户口径：匹配「闪购」没问题，「飞猪」是错误的。

## 事故链（OCR 行取自 App 同款引擎 --ocrdebug 转储）

1. `splitOrderBlocks` 的不变式是「块 = 上一条实付行之后到本条实付行」——
   首块起点是**图顶部**，于是状态栏/搜索行/标签栏（全部订单｜购物｜闪购外卖｜
   **飞猪旅行**）/筛选 chips（全部｜待发货｜待收货｜待评价｜已关闭）整组并入首块
2. 商户匹配对块内**全部行**做 contains 扫描：「飞猪旅行」含「飞猪」（种子别名）
3. 同长度命中先到先得（`bestLen >= alias.length` 跳过）——种子表里「飞猪」在
   用户学习的「闪购」之前 → 飞猪胜出
4. 本单真商户行「闪购YY」置信度 0.74，被 MIN_LINE_SCORE(0.78) 滤出块——
   块内仅剩标签栏能命中「闪购」，误命中土壤由此形成
5. 连带：快路径类别判定同用种子表 → 首块类别被带成「交通」（飞猪的种子类别）

## 修复（两件套，契约三耦合未动）

1. **`OcrPostProcessor.uiStripLines`**：结构判定页面 UI 条带（tab 栏/筛选 chips/
   动作图标行）= 同一水平带（top 差 ≤12px）内 ≥3 条短文本并排（宽 ≤210px、
   间隙 8..150px、不含数字/货币符号）。不用关键词表——标签行与订单行合并 OCR
   时关键词会漏网。条带整体出局：不进块（prompt/金额/日期候选/快路径），
   也不进商户匹配。
2. **`OcrPostProcessor.merchantMatchLines`**：商户匹配范围改为「区块 y 范围内的
   原始 OCR 行剔除条带」——不设置信度门槛，把「闪购YY」(0.74) 这类承载平台名/
   商户名的低分徽标行捞回；逐块取范围保持票 30 多单各配各的行。

效果：首单 飞猪 → **闪购**（本单行内命中）；次单 闪购 不变。
