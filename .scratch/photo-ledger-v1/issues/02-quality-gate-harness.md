# 02: 质量闸门评分与数据集

**What to build:**
质量闸门 (Quality Gate) 的评分 harness：以用户提供的真实订单截图数据集（约 30–50 张，硬字段人工标注：实付款金额、日期）为输入，批量调用正式提取管线（截图 → OCR → 文本小模型 + GBNF → Draft），一条命令产出逐字段正确率报告。

管线形态随 ADR-0004 变更：提取 = OCR（RapidOCR/PaddleOCR 系）+ OCR 后处理 + Qwen3-0.6B 文本模型 + GBNF 约束（同 01 验证的文法）。**OCR 后处理是本票的质量重心**（01 对比实验实证：模型大小不是瓶颈，OCR 输入碎片化才是）：

- 日期行聚类与规范化：把「下单时间2026-09-10 11:19」「09.10」角标、缺失年份等碎片拼回干净日期（01 实验中 0.6B/1.7B 都修不好的 0909-09-09 类畸形在此源头解决）
- 金额规范化：全角/半角、¥ 前缀粘连、千分位、小数点丢失校正
- 多订单截图处理策略：一图多单的拆分规则先定义再评分（01 实验中模型默认只取最后一单）

闸门标准（沿用 ADR-0001 数字，解释权在 ADR-0004）：硬字段（实付款金额、日期）≥95% 完全正确；软字段（商家、类别）≥80% 且错误可一眼修正。**不达标也是有效交付**——失败报告同样进账，触发备选路线讨论（VLM 复活或 OCR 预处理加深），不硬上。

模型主选 Qwen3-0.6B Q8_0（01 对比实验结论：1.7B 耗时 2.3 倍无质量优势）。 harness 必须支持换模型重跑（0.6B/1.7B/其他 GGUF 文本模型）以保留对比能力。

数据集由用户提供：真实订单截图 + 人工核对过的硬字段标注表。截图与标注均不出设备/不出本机。

**Blocked by:** 01-resolved (桌面提取管线打通), 12 (OCR 提取管线正式化——harness 跑的是正式管线)

**Status:** ready-for-agent

- [ ] 数据集就位：真实截图 ≥30 张 + 硬字段人工标注，存放于本机不入 git（.gitignore 或独立目录）
- [ ] 一条命令对全量数据集跑提取并产出逐字段正确率报告（含每张截图的逐字段对比明细）
- [ ] OCR 后处理模块实现并通过单测：日期行聚类/规范化、金额规范化、多单策略
- [ ] 报告明确给出闸门结论：PASS（硬≥95% 且软≥80%）或 FAIL（附失败字段分布 + OCR 后处理失败案例归因）
- [ ] 模型替换、prompt 调整、口径变更后可重跑同一 harness（S1 接缝的可重复性）
