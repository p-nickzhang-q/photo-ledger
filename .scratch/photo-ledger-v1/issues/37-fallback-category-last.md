# 票 37：兜底类别「其他」恒排末尾

- Owner: agent（QoderCN）
- Created: 2026-10-29
- Status: Resolved

## Resolved

- 结论（2026-10-29）：已实现并真机验证通过（vivo V2183A）。
- 证据：类别管理页「其他」固定最后，无拖拽把手、拖不动；把它上面的类别拖到底部，
  落点停在「其他」之前；冷启动后仍保持。编辑页类别快选同样「其他」垫底。
- 单测：`CategoryTest` +2（重排传入中间位置被忽略 / 库里 sort_order 被改到最前仍排末尾），
  连带更新 3 条受影响的断言（新增类别、备份 round-trip ×2），全绿。

## 背景 / 动机

用户反馈：票 36 上线拖拽排序后，兜底类别「其他」可以被拖到列表中间。用户口径：
**要么不显示，要么始终在末尾**。取「始终在末尾」——不隐藏，用户仍知道它的存在。

## 根因

「其他」不是普通类别：删类别时其下账目统一归入（`FALLBACK_CATEGORY`），
位置本身没有语义；但拖拽把它当普通项参与重排，既可被拖到中间，
库里 `sort_order` 也会落在中间，新增类别还追加到它之后。

## 方案

两层各自兜住，避免只靠 UI：

1. **读路径**（`LedgerRepository`）：`categories` Flow 与 `categoryNames()` 统一走
   `fallbackLast()`——非兜底类别保持 `sort_order` 相对顺序，「其他」压到末尾。
   影响面：管理页、确认页/编辑页类别快选、提取 prompt 的类别清单。
2. **写路径**（`reorderCategories`）：不论传入顺序如何，落库时把「其他」排到最后再编号，
   保证库内顺序与展示顺序一致（防并发/异常调用留下中间态）。
3. **UI**（`CategoryManageScreen`）：可拖拽集合 = 非兜底类别；「其他」单独渲染为
   末尾静态行（无拖拽把手、无重命名/删除），保持「兜底类别」标注。

## 验收

- 管理页：「其他」恒末尾、拖不动；其他类别拖到底部落点在其之前
- 冷启动 / 备份恢复后顺序不变
- `CategoryTest` / `BackupRoundTripTest` 全绿
